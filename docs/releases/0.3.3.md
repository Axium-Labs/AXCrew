# AX Crew 0.3.3

- Add an optional Distributed Control Plane with distinct Host, AX Instance and
  Execution identities, allowing multiple runtimes on a Host and concurrent work.
- Schedule using approved AX roles/Skills/MCP/Tools/models/permissions/environment
  tags plus resource reservations shared by instances on the same Host.
- Persist Durable Tasks, ordered Events, immutable SHA-256 Artifacts and versioned
  Workflow State. Central ownership, incarnation/generation fencing, idempotent
  requests, retries/cancellation and checkpoint recovery survive worker loss and
  Crew restart without a permanently live Coordinator Agent.
- Add the desktop **Distributed / 分布式协作** sidebar management page: enrollment
  and private worker config, Host capacity/policy, task submission/attempts/errors,
  Workflow checkpoints, cancellation/retry, Artifact downloads and observations.
- Keep legacy APIs, single-machine AX and existing device controls available.
  Complete AX Session/Memory are not replicated; selected results/checkpoints and
  explicitly published artifacts are shared by logical project identity.

Validation during development: 15 existing server tests plus 8 distributed
regressions passed; desktop 114 Vitest tests and 4 browser layout/recovery checks
passed, along with the legacy sidebar check and four existing process suites.
Actual three-AX-process/two-logical-Host collaboration verified failed testing,
analysis, Patch transfer, retest, auth scoping and Crew restart. Android build,
unit tests and lint passed during feature development. Production Windows x64
frontend/gateway/NSIS builds passed; no additional release-time tests were run.
Android version and release assets are unchanged.

Limits: one authoritative Crew process with SQLite, at-least-once attempts,
resource reservations rather than OS quotas, 8 MiB Artifact limit, no automatic
GC/replicated consensus. Real physical networking/TLS/GPU isolation has not been
tested; the fake-model integration fixture explicitly uses sandbox off.
Requires AX 0.3.7 workers. See [Distributed Collaboration](../distributed-collaboration.md).
