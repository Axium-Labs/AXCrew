# 桌面端行为

[English](README.md) | **简体中文**

本文说明 AXCrew 桌面客户端的当前行为。构建、安装和打包说明见 [apps/desktop/README.md](../../apps/desktop/README.md)。

<a id="command-search"></a>
## 命令搜索

标题栏命令按钮和 `Ctrl/Cmd+K` 会打开独立的命令面板，搜索框位于面板顶部。最近对话、命令、页面、Crew、设备和任务分组展示，各组有独立标题，紧凑的结果行带有类型标签。未输入查询时，最先显示最多五条最近对话；搜索时检查所有对话标题及其他现有条目，合计最多返回 35 条结果，空分组不显示。结果沿用现有导航路由；命令面板不新增服务端 API 或命令执行路径。

只有结果区域纵向滚动，搜索栏和底部键盘提示始终可见。长标题截断显示，悬停提示展示完整标题；面板使用当前显示主题，适配窄窗口和高度较小的窗口。方向键选择结果，并将当前项滚动到可见位置；Enter 打开结果，输入法组合输入期间除外。按 Escape、点击 Esc 按钮或面板外部均可关闭；原控件仍存在时恢复之前的焦点。重新打开后清空查询和选择。搜索输入框通过 combobox/listbox 无障碍角色暴露当前选项。

<a id="settings-pages"></a>
## 设置页面

桌面端的管理、设置、计划、产物和对话元数据界面复用通用按钮、输入框、菜单、单选控件和对话框。标准对话框滚动正文时，标题栏和关闭按钮保持可见。对话重命名、项目分配和删除确认使用同一套基础控件；删除仍需明确确认。多步骤协作编辑器在通用对话框内部保留自己的正文和底部布局。

概览将现有任务、设备和审批数据整理为计数卡片和专题面板；数据到达前不显示计数。管理列表、状态标签、筛选器和空状态采用统一样式。计划与产物表格在可用宽度缩小时改为紧凑行布局，原有操作仍可访问。设置页在侧边栏排列搜索和分组导航；窄窗口使用横向导航条，并将所选分区滚动到可见位置。主题和语言设置继续作用于这些界面。

聊天界面根据 AX 提供的实际次数显示模型连接进度，例如 `正在连接模型（1/5）…` 和 `正在重新连接模型（2/5）…`。模型响应后，正常的思考或输出替换连接状态。模型最终连接失败时显示 `模型连接失败（已尝试 5/5 次）`，可展开的错误详情位于折叠工作区之外。最终状态保存在任务输出中，重新打开时仍可查看；桌面通知也使用同样的模型连接措辞。认证、权限、部分流错误或连接预算可能使尝试提前结束。事件由配套 AX 运行时提供。调度仍沿用现有任务生命周期状态，聊天界面明确展示模型失败。

停止对话后，重新加载历史期间会保留已提交消息、此前轮次和已接收的部分输出，即使 AX 尚未为当前轮次保存检查点。已取消和失败的任务会将实时输出与已保存历史合并，而不会用空结果覆盖对话记录。配套 AX 运行时会先保存普通消息，再准备文件基线，因此重新打开会话时仍保留已提交消息。尚未写入 AX 检查点的部分输出保留在当前桌面应用的实时对话缓存中；应用重启后只能回放已保存的输出。

配合匹配版本的 AX 运行时，大型或响应缓慢的工作区不会在准备自动文件变更预览时无限期阻塞聊天。AX 会限制并取消快照工作进程；无法提供完整文件变更预览时，对话记录会予以提示。工具执行仍可使用。参见 [AX ACP 限制](https://github.com/Axium-Labs/AX/blob/main/docs/acp-crew.md)。

<a id="personalization-and-automatic-learning"></a>
### 个性化与自动学习

设置 → 个性化（`/settings/personalization`）将工具触发的记忆写入与**自动学习（自我进化）**分开管理。记忆工具开关控制记忆写入；自动学习有独立的全局开关，对应 `ax personalize --evolution`。只有同时启用记忆和自动学习，才会执行自动分析。

进化数据归属于项目，而非 AX 全局技能列表。卡片使用所选项目目录，未指定时回退到 Crew 默认工作目录，并验证该目录是否位于本机且有效。界面显示实际本地项目路径及该项目的学习数据。若没有有效本地项目，可在卡片中选择本地项目文件夹。

**自动学习**卡片读取本地 AX 的 `evolution status`、`evolution skills` 和 `evolution show` JSON 输出。待审核技能以纯文本展示完整 SKILL.md，并提供包含证据 ID 和任务摘要的证据概览。桌面端计算文本的 UTF-8 SHA-256 摘要，与待审核版本的摘要比对。接受和拒绝操作将该摘要传给 `evolution review`，因此提案变更后必须重新审核。已学习技能显示状态、使用次数和成功次数，并提供归档操作。运行时状态默认折叠，包含待分析项、上次分析时间、连续失败次数和退避时长。存在待审核技能时，设置导航中的“个性化”以现有未读圆点样式标记。

所有调用均经过桌面的 `ax_tui_command` 桥接。全局个性化设置使用本机 AX 主目录；进化命令在经过验证的本地项目文件夹中运行。即使 Crew 连接远程服务器，此界面也只支持本机 AX 运行时；进化数据不会写入 Crew 服务器，也不会经服务器转发。本地 AX 缺失、无法运行或版本尚不支持进化命令时，卡片展示不可用原因，不弹出错误警报。使用此功能需要配套 AX 运行时。

<a id="goal-policies"></a>
### 目标策略

设置 → Goal（`/settings/goal`）可编辑 AX 全局默认值或所选项目的 Goal 模板。**启用 Goal**会让普通新任务采用对应作用域的策略，通过 AX 的 `enabled` 字段保存，默认 false。修改开关后需点击“保存策略”才生效；保存失败时保留草稿。禁用后仍保留所有规则和显式 Goal 命令。已有 Goal、暂存答案和恢复操作沿用已保存的策略。配套 AX 构建在共享 CLI/TUI/ACP 提示路径中支持自动接纳普通任务为 Goal；分布式工作节点保留控制器策略。界面提供确定性／模型验证、All/Any 条件、命令／HTTP／已注册主机／MCP 验证器及其 ID、版本、引用、超时和显式安全重放设置，还提供累计执行上限以及保守的进度阈值与动作。高级主机输入须为 JSON 对象；保留的 Goal 上下文由运行时提供。保存仅验证配置，不执行配置。

原生 `ax_goal_settings` 桥接调用 `ax goal-settings --scope global|project`；写入时通过标准输入传入完整 GoalConfig JSON，重置或继承使用 `--reset`。持久化由 AX 负责（`$AX_HOME/config.json.goal` 或 `.ax/goal.json`），Crew 不另存一份策略。全局设置无需工作区；项目写入会验证所选工作区。读取失败时可重试；写入失败保留草稿并显示 AX 错误。需要配套 AX 构建。

默认值影响显式创建的 Goal，以及启用后创建的普通新任务。已保存 Goal 保留自身策略。预算为零表示不增加上限；轮次与时间限制仍由运行时执行。Token 和费用限制需要完整实测数据；估算值或不可用的计费数据不会被宣称为精确硬上限。页面区分保留本地状态、后台执行和 Crew 负责的 Durable Task 接管，不会开启自动恢复或扩大主机权限。本机 AX 设置界面不改变远程设备或 Android 的设置契约。

验收规则、自定义验证器、执行预算、进度与恢复默认折叠。点击横跨整行的标题，或按 Enter/Space，可分别展开字段。折叠保留编辑内容，保存也会包含隐藏字段。表单输入框适配主题，文本域边框清晰可见，支持键盘焦点；窄窗口下字段采用单列布局。

费用上限以美元输入，输入／输出估算费率以每百万 Token 的美元金额输入。小数最多支持六位，精确转换为现有整数微美元字段；已保存值以美元展示，金额不变。上限为零表示不增加限制；费率留空表示未配置，零费率表示免费。负数、超过精度的数值和不安全的整数金额会阻止保存，不会四舍五入。AX 持久化与原生桥接协议沿用现有单位和字段。

连接功能位于外层**连接**（`/connect`）页面，包含“控制本机”“控制其他设备”和 SSH 标签页，涵盖手机授权、配对 AX 设备和持久保存的 OpenSSH 主机。设置中没有重复的连接页；旧 `/settings/connections` 链接重定向到 `/connect`。**系统**（`/settings/system`）包含服务状态、本机系统指标、桌面行为和 Crew 更新。模型设置按账户登录、API 密钥和环境配置提供商分组。WorkBuddy 中国区和国际区使用独立账户。账户登录展示可点击或复制的网址；关闭对话框取消等待。AX 保存凭据，并在授权后刷新模型列表。

Codex 账户登录先提供**浏览器登录**和**设备码登录**两种方式。两者等宽，使用相同的中性样式，均不标为默认或主要操作；窄对话框中纵向排列。浏览器方式仅在明确点击后打开所显示的授权网址，AX 接收受 PKCE 保护的本地回调。设备码方式在独立、可选择的区域显示完整一次性代码，提供复制代码按钮和 15 分钟有效期说明。重试会返回方式选择界面。WorkBuddy 沿用浏览器流程及区域账户隔离。

原生 `ax_begin_login` 命令为 Codex 接受 `method: browser | device`，并以 `auth login openai-codex --method <method> --json` 启动 AX。进度先使用 AX 定义的标准错误 JSON 协议（`type`、`message`、`url`、`code`），再进入现有 `ax-login` 事件通道。不预设代码长度或格式；旧式可读提示按指令上下文识别。完成事件发出前会读取完提示输出，前端会缓存早于登录 ID 到达的事件。打开网址仍受 HTTPS 主机白名单限制。需要支持 `--method` 和 `--json` 的 AX 构建；安装此更改时 AX 与 AXCrew 应一并更新。REST/Android 契约不变。

<a id="computer-use-and-browser-settings"></a>
### Computer Use 与浏览器设置

设置 → Computer Use（`/settings/desktop`）包含两个共用样式的胶囊开关，以及带整行数字输入框的限制卡片，适配现有深浅主题。本地 `ax_computer_use` 命令调用 `ax computer-use` 读写 AX 全局配置，无需选定工作区或请求服务。Crew 不单独保存一份配置，也不显示模拟成功。桥接与本地聊天运行时共用 Crew 现有的 `AX_HOME`：优先采用显式环境覆盖，否则使用用户的 `~/.ax` 目录。

Computer Use 和截图默认开启；AX 保留明确保存的禁用设置，升级时也如此。设置缺失时使用 AX 默认值；节点／图像默认值为 1200/1280。AX 返回支持状态和内置范围限制：1–10000 个节点，图像长边 320–4096 像素。开关修改立即保存，整数编辑在失焦或按 Enter 时保存。写入期间锁定控件；失败保留已确认值，读取失败可重试，无效数字仍可编辑。目前支持原生 Windows；不可用的环境无法启用。启用在 AX 构建下一轮工具注册表时生效；禁用还会拒绝此前已有访问权的注册表发起的后续辅助调用。AX 负责限制、审批、有界隐私扫描和实际窗口／控件操作。运行时契约及渲染器限制见 AX 的 `docs/computer-use.md`。

Computer Use 包含应用访问设置；浏览器设置包含实际生效的 Browser Use 开关和网站访问设置。共用 HostPermissionsPanel 调用 `ax_host_permissions`，后者调用 AX 的前置 `host-permissions` CLI，使用 Crew 相同的全局 AX 主目录，无需工作区、网关或模型。可添加、删除规则，或将规则改为询问、始终允许、拒绝；删除规则后恢复为询问。应用路径和网站来源在可用宽度内换行。写入时锁定控件，写入失败保留已确认值，读取失败可重试。应用和网站规则选择器，包括新增规则的选择器，均使用与模型及执行设置相同的主题化 `SettingsSelect`。输入框与操作按钮共用标准高度、圆角和键盘焦点样式。

浏览器操作由 AX 的真实工具运行时提供。本地 Windows 桌面任务使用下文的嵌入式浏览器桥接，无需安装 Node/Playwright。独立 AX 与远程 Host 仍使用 AX 管理的 Playwright 会话，需要 Node、Playwright 和受支持的浏览器。两条路径都执行网站权限检查，阻止跨来源资源、重定向和 WebSocket，因此部分网站无法完整运行。

应用／网站访问与文件／终端沙盒模式相互独立。Computer Use 中已允许的应用涵盖普通操作，显式任务审批规则和能力拒绝仍生效。浏览器动作审批独立处理。ACP 访问提示通过现有动态权限对话框提供“仅一次”“本会话”“始终允许”和“拒绝”。通用动作审批不会授权新应用或网站。桌面控制交由 AX 的 Windows UIA、Linux AT-SPI 或 macOS Accessibility 后端；Unix 需要驱动依赖，macOS 需要系统隐私权限，Wayland 限制原始输入与截屏。参见 [AX Computer Use](https://github.com/Axium-Labs/AX/blob/main/docs/computer-use.md)。尚未实现原生 Windows/macOS 操作系统级工作区隔离，显式受限模式仍会在无法提供隔离时拒绝运行。参见 [AX 主机访问](https://github.com/Axium-Labs/AX/blob/main/docs/host-permissions.md)。

<a id="local-system-metrics"></a>
### 本地系统指标

桌面系统页面中的卡片挂载期间，每三秒刷新本机 CPU 使用率、物理内存使用量、Windows 系统卷已用／总容量及系统运行时间。CPU 使用率由 Windows 空闲、内核和用户计数器的增量计算，首次在阻塞线程池采样 250 ms；未活动间隔超过十秒时重新采样。实际零值显示 `0%`，大于零且低于 0.1% 的值显示 `<0.1%`，不会舍入为零。其他百分比最多保留一位小数。

内存和磁盘容量采用二进制 **GiB**（命令的 `_mb` 字段为整数 MiB）。磁盘标签包含实际 Windows 卷盘符，从 Windows 目录推导，不硬编码 C:。容量表示当前用户可用的空间，计入磁盘配额，不是所有磁盘容量之和。系统运行时间使用 Windows 运行时间计数器，按所选语言展示。加载中、读数不可用和命令失败分别呈现；失败可重试，并隐藏过时读数。缺失或失败读数为 `null`，不使用虚构容量或零使用率兜底。

`get_system_info` 是本地 Tauri 命令，浏览器预览不会轮询它。Windows 使用原生 CPU、内存、磁盘和运行时间采集器；Linux/macOS 使用 sysinfo，显示 HOME 所在文件系统，而非 Windows 卷。GPU 通过 `nvml-wrapper` 调用已安装的 NVIDIA NVML 驱动，按需加载后复用。每个受支持 NVIDIA GPU 单独显示名称、使用率及以 GiB 表示的专用显存已用／总量。驱动、权限或不支持字段导致的失败保持为不可用。尚不采集 Intel/AMD GPU 遥测；没有 GPU 读数不表示主机没有 GPU。`gpus` 数组包含逐设备可空字段；旧 `gpu_count` / `gpu_memory_mb` 仅涵盖 NVML 设备。主机逻辑处理器超过 64 个时，`GetSystemTimes` 仅覆盖调用线程的主处理器组。

<a id="window-closing-and-quitting"></a>
### 窗口关闭和退出

系统设置中有一张**桌面行为**卡片。**关闭窗口时隐藏到系统托盘**默认开启，延续旧版本的后台服务行为。开启时，关闭主窗口仅隐藏窗口，服务与任务继续运行；托盘“显示”操作恢复窗口并取消最小化。关闭此选项后，关闭主窗口会退出 AX Crew 并停止本地服务。卡片只包含该关闭行为开关。无论开关状态如何，托盘“退出”始终会停止服务并退出应用。其他窗口不受主窗口关闭偏好影响。

原生外壳在 UI 打开前，从应用数据目录读取 `desktop-settings.json`。`get_minimize_on_close` 返回实际原生状态；`set_minimize_on_close {enabled}` 原子持久化设置，并返回保存后的布尔值。打开设置页不会写入或重置此偏好。仅保存成功后更新 UI 状态；读取／保存错误保持可见，读取错误可重试。旧版仅存于 localStorage 的偏好不再使用，因为它从未改变旧版原生关闭行为。浏览器预览禁用这些桌面控件。运行时关闭失败不会将应用误标为正在退出。

<a id="chat-execution-view"></a>
## 聊天执行视图

<a id="completion-reminders-and-unread-results"></a>
### 完成提醒和未读结果

桌面端全局监听实时 `task.completed` 和 `task.failed` 事件，在其他页面或对话打开时也如此。默认完成策略沿用 Codex 的失焦模式：切换至其他应用、最小化 Crew 或隐藏到托盘时，发出短促 Windows 提示音和系统通知。Windows 任务栏闪烁提醒但不抢焦点；存在未读结果时，任务栏叠加图标和托盘图标保留一个鸢尾色小圆点。提示音嵌入桌面可执行文件，经原生异步播放，不依赖 WebView 自动播放。系统通知权限只影响通知弹窗。非 Windows 外壳使用原生徽章计数 API；内嵌提示音与任务栏叠加图标仅限 Windows。

Crew 获得焦点时，其他对话完成只在“最近”、所属项目行和“会话”导航添加未读圆点；当前可见对话保持安静并视为已读。隐藏的主聊天／侧聊不会被确认已读，侧聊标签也显示未读结果。返回应用只清除实际正在查看的对话结果，保留其他未读圆点及图标徽章。打开结果或删除其对话会清除对应圆点。失败结果采用相同策略；取消不触发完成提醒。通知显示对话标题，不显示最终答案正文。

`store/attention.ts` 将未读轮次 ID、对话标识及有界事件去重信息保存到 localStorage。焦点和可见聊天注册信息为临时状态。后续任务 ID 归属同一设备／AX 会话标识，因此“最近”和项目行共享未读状态，阅读时清除所有轮次的未读标记。重启恢复徽章，不重放提示音，也不将历史已完成任务标为未读。这是实时桌面提醒，不是应用完全退出后的后台推送；断线期间遗漏的事件不重放。

`lib/completionNotifications.ts` 负责焦点订阅、通知权限及串行原生徽章更新；`src-tauri/src/completion_attention.rs` 负责原生 `completion_attention {unreadCount, alert}` 命令。现有 REST/WebSocket 契约和 AX 运行时保持不变。

<a id="questions-during-ordinary-chat"></a>
### 普通聊天中的问题

AX 调用 `request_user_input` 时，主聊天和侧聊在输入框上方显示紧凑的浮动提问面板。面板与输入框左右对齐且等宽，间隔 8 px，最高 300 px；覆盖对话记录，不撑开布局。带编号的选项行显示标签，悬停时显示描述；可选的单行文本输入可提交自定义答案。关闭按钮将面板收起为可重新展开的标签，不回答问题，也不丢弃草稿。点击选项或提交文本后，继续同一 Crew 任务和 AX 会话。普通输入框中的文字也可回答已挂起的问题；选项 ID、标签和从 1 开始的编号均可选中给定选项。提问独立于自动 Goal 开关和权限对话框。

AX 完成挂起过程之前，选项保持禁用。已挂起任务使用现有 `waiting_user` 状态，释放执行槽，不标记完成，也不发出完成通知。保存的任务状态使重新打开对话或重启 Crew 后能够恢复当前问题。自定义答案草稿使用现有按对话存储的本地草稿库，以任务／问题为键；导航和提交失败时保留，主聊与侧聊不混用。已回答的工具回执在历史中显示问题和便于阅读的选择结果。

`POST /api/sessions/{task_id}/answer` 提交问题标识以及一个选项或文本答案。事务性状态／标识检查拒绝重复、过期、空白和无效提交。现有 `/message` 路由可回答已挂起问题，不创建后续任务；该回答路径拒绝附件和上下文，并由输入框保留。Gateway 通过本地、SSH 和配对设备传输转发结构化 `_meta.axGoal` Answer 元数据，其中携带 AX 保存的 Goal／问题标识。AX 必须支持结构化回答；其共享提示路径保留传入标识，不会拿另一问题重新解释答案文本。问题／任务状态与权限分离，绝不授权工具。

<a id="conversation-history-and-execution"></a>
### 对话历史与执行

打开本地 AX 对话时，同时显示原始对话记录和输入框。首次发送通过 `/api/sessions/attach` 记录 Crew 绑定，再发送 `/api/sessions/{task_id}/message`，恢复原 AX 会话和工作区。没有单独的只读或继续按钮。已有接管关系会复用；发送失败保留草稿和附件。视图切换至续接轮次时，本地回放保持可见。搜索列表不会卸载已选对话。

本地索引保留显式标题。标题为空或为 `ACP session` 时，使用首条用户消息，将空白折叠，最多 80 个字符；空对话显示未命名标签。此规则只改变展示，不修改 AX 索引或对话记录。桌面中已接管但标题为占位符的对话，也使用该本地索引。用户重命名的标题优先。

聊天区域按用户轮次组织工作内容。进度文字、补充指令和工具调用在执行中及停止后均保留接收顺序；仅相邻工具调用合并进一个折叠组，组间进度仍可见。思考片段有独立且默认关闭的展开控件，绝不提升为答案。已回答问题的回执与对应提问调用并列。外层工作区默认展开，完成或取消后也如此；手动折叠不丢失各工具的独立展开状态。当前 Crew 任务只有在状态为 completed 时才将最后一条助手消息提升为最终答案；取消、失败或等待用户输入时不会提升。没有 Crew 任务状态的独立 AX 历史保留旧的末条助手消息回退规则。延迟回放的子调用不会移除已完成答案。

已保存检查点与实时片段根据消息／调用标识或兼容的文字前缀合并，不按思考／助手行的序号匹配。仅存在于流中的行相对于共有行定位，接收的流顺序用于解决回放顺序差异，避免检查点遗漏的思考出现在末尾，或缺失的进度覆盖其他消息。取消或失败时，未结束的工具行显示“已停止”并停止计时；已完成／失败结果保留真实状态。此展示不虚构命令退出码，也不改变已存工具结果。

主聊与侧聊输入框可在执行期间发送。发送或按 Enter 会将补充指令加入同一任务和 AX Goal，不打断流式输出或重启工具。输入框只有一个动作按钮：执行中或等待回答时，空输入显示“停止”；加入指令、答案文字或附件后切换为“发送”。主聊与侧聊均不同时显示停止和发送。补充指令在工作详情中保留时间顺序，以稳定消息 ID 支持历史回放。Gateway 经现有本地／SSH／设备连接转发 `_ax/steer`，仅在 AX 确认接受后返回当前任务。等待权限不阻止补充指令，也不隐式批准工具。当前模型、思考强度和权限选择只作用于后续轮次；补充指令不改变正在执行轮次的设置。旧远程 AX 可能拒绝新扩展；发送失败保留草稿，并提示需要更新 AX。

每次工具调用显示为低对比度的紧凑单行。操作标签和工具标题跟随界面语言，命令文字、路径、查询和真实输出保持原样。网页行显示页面数和主机名，避免冗长编码 URL。同一调用 ID 的开始、成功和失败状态原位更新。点击展开后显示真实工具类型、操作及压缩结果；原始输出需再次展开，长输出在卡片内部滚动。错误不会变为成功。超过一分钟以分钟展示时长，超过一小时以小时展示。每个结束轮次显示文件变更卡片；ACP `turn_changes` 优先于累计补丁统计，历史回放保留卡片。

AX 对比本轮执行前后的工作区内容，排除未触及的用户既有修改，包含创建、删除和普通非 Git 文件。权威快照为空时清除早先增量变更。点击文件或“查看变更”打开文件面板的**审查**标签。文件面板与主聊天共享可调整分隔布局，默认占导航和会话列表以外剩余空间的 45%。停靠时预览至少 420px（聊天／详情至少 320px），最多 980px；主聊天至少保留 520px。无法同时满足最小宽度时，预览改为抽屉，最多占工作区宽度 94%。布局还可仅显示侧栏，或返回主聊天，不改变文件标签。审查列出所选对话轮次的变更文件及行数。直接打开文件面板显示最新轮次，也支持已接管的本地 AX 对话。保存的 unified diff 在重开后保留新旧行号及 +/- 符号。选择另一变更文件会返回 Diff。删除文件、二进制变更及没有 diff 的旧记录均显示明确说明。**当前文件**读取本地实时 UTF-8 文本，最多 256 KiB；不会用当前文本代替缺失的历史 diff。

**+ → 打开文件**菜单、文件夹按钮或**所有文件**开关打开工作区浏览器。目录原位展开、按需加载，阅读器旁保留目录树。目录列表包含隐藏和忽略项，不以 500 条截断；跳过符号链接。筛选仅作用于已加载目录中的路径，折叠目录仍可导航，并非递归全项目搜索。文件在可独立关闭的标签中打开，重复打开选中现有标签。切换聊天／详情或收起侧栏时保留标签，更换对话／工作区时重置。可隐藏目录树扩大阅读空间。Markdown（`.md`、`.markdown`、`.mdown`，不区分大小写）默认渲染预览，可切换源码；其他 UTF-8 文本包括空文件按源码打开。刷新重新加载目录和当前文本；支持复制路径及文件引用。**编辑**为已成功读取的本地文件打开源码文本框；**保存**或编辑器中的 Ctrl/Cmd+S 写入文件；**取消**丢弃草稿并重新加载磁盘内容。Markdown 预览可渲染未保存草稿。草稿保留最初读取的文本，在本次应用运行中跨刷新、关标签、关面板和对话导航保留，退出应用后不持久保存。保存中锁定编辑，失败保留可见草稿。原生写入命令支持不超过 256 KiB 的已有 UTF-8 文件，验证规范化后路径在工作区内，比较磁盘字节与最初读取内容，再通过同目录暂存文件替换。文件已删、不可读、内容超限或检测到外部编辑时失败，不覆盖磁盘。冲突时应先复制草稿，再取消并重新加载，然后将修改应用于当前文本。这是乐观检查；最终检查和替换之间不锁定外部程序。统一使用 CRLF 的文件保存后保留行尾。成功写入更新当前文件缓存和目录大小，历史 diff 不变。方向键／Home／End 导航文件标签；文件面板内 Ctrl/Cmd+P 打开工作区树。极窄宽度下目录树覆盖阅读器，打开文件后自动隐藏。

本地文件浏览需要桌面应用，不要求 Crew 成员。远程／SSH 对话可审查已保存 diff，但不能经本机文件系统读取远程路径。工具返回的绝对路径只有在规范化后位于工作区内才可预览。编辑沿用相同的仅本地边界，不初始化 Git 仓库，也不撤销历史变更。

输入框随文字和面板宽度自动增高，达到高度上限后内部滚动。Enter 发送，Shift+Enter 换行，输入法确认不触发发送。发送失败保留草稿。未发送文本按对话保存在本地，在新建／已有聊天切换、延迟会话绑定及应用重开后保留。分支草稿在导航中使用独立键，但分支上下文仅存内存。图片附件只保存在内存，关闭应用后不恢复。用户消息可复制。每个完成轮次在答案及文件变更下方只有一条答案工具栏；中间叙述、思考和工具没有复制／分支工具栏。答案分支按钮根据该答案之前的文本打开独立会话，继承工作目录和执行环境，不复制工具状态，不改变原会话。从分支返回后按调用 ID 重载原工具记录；历史合并保留更完整的已存／原始结果。

新会话页面刻意保持简洁，不显示欢迎标题或建议标签。输入框在聊天面板内保留 20px 的下方空间。仅在新聊天首次发送前，嵌入式工作区栏才与输入框顶部相连。发送时隐藏该栏；运行中、已完成或重新打开的会话也保持隐藏。首次发送失败会恢复该栏并保留草稿；再次新建聊天时重新显示。
紧凑控件高 28px，常规文字为 13px，图标为 16px；弱化文字让工作区栏在视觉上次于输入内容。Project、This computer 和 Cloud 控件默认使用透明背景，在悬停或菜单打开时提供轻微反馈。透明文件夹按钮显示当前项目目录，点击可选择其他目录；圆角的“此计算机 / This computer”按钮打开向上的工作位置菜单，并勾选本地选项。选择本地时保留所选项目目录；选择 Cloud 后显示 Choose environment，只有在线的配对 AX/SSH 环境才能发送。对于 AX 设备，模型选择器使用配对主机的模型目录；对于 SSH，使用本地 AX 模型。新会话绑定所选模型，已有会话的目录、设备和模型保持固定。
发送按钮旁弱化显示的模型/强度入口打开紧凑卡片：Fast 在左侧，中央按钮在模型名上方显示当前强度，没有重置强度按钮。卡片宽 260px，圆角轨道高 24px，滑块为 28px，并跟随应用主题强调色。中央模型按钮空闲时透明，仅在悬停、键盘聚焦或模型菜单打开时高亮。打开卡片时焦点落在卡片本身，避免 Fast 一直保持焦点高亮。
点击中央按钮会打开独立的、按供应商分组的模型菜单，提供选中行、悬停/焦点反馈和方向键导航。选择模型或按 Escape 返回卡片；再次按 Escape 或点击外部关闭卡片。
主题强调色的分档 **思考强度 / Reasoning effort** 滑块支持点击、拖动和方向键，下方不重复列出全部强度标签。滑块与填充在档位间平滑移动。拖动使用 80ms 的阻尼响应，平滑吸附到邻近的模型目录档位，同时允许档位之间自由移动；释放后在 200ms 内缓动至最近的受支持档位，包括在轨道外释放的情况。填充终点位于滑块中心下方，与滑块同步移动；独立裁剪的圆角轨道使两端保持圆润。最小值时滑块完全覆盖填充；键盘焦点描出轨道边框，不在滑块周围添加彩色光晕。
Fast 为滑块提供向前冲刺效果：细小粒子从其下方出现，向左加速形成逐渐淡出的尾迹，按 0.9 秒循环，并裁剪在轨道已填充的区域内。未填充一侧仅保留静态档位标记。系统减少动画偏好会禁用粒子与滑动过渡。
档位仅来自该模型的 AX 目录 `reasoning_efforts`，保留供应商协议值及目录默认值。过期选择回退到所选模型的配置/目录默认值，或首个受支持值。能力缺失或为空时禁用强度选择，并省略请求参数。Tauri 桥保留这些字段。新轮次和后续消息都会传递 `reasoning_effort`；修改该设置不会影响正在执行的工作。配对 AX 使用自身目录，SSH 使用本地 AX。会话内容直接从消息开始，不显示 AX Session ID 或重复的本地会话元数据行；AX Session ID 仍可在 Details 侧栏查看。选择 YOLO 模式时，权限按钮变为橙色。

对话记录左边有一条低干扰轮次导航线。悬停或键盘聚焦可预览用户请求和最新答案文字，点击标记滚动到对应轮次。它由对话历史构建，不创建任务或分支。

原生窗口最小尺寸为 640×480 逻辑像素。WebView 缩放固定为 1，显示器 DPI 由系统处理；窗口变宽不会放大字体。单一布局管理器测量实际外层工作区和右侧停靠终端，优先为聊天预留目标 560px、最小 520px；先收起主导航，再收起会话列表，最后将预览改为抽屉。有效视口极小时，导航轨也隐藏，可从标题栏打开。整个视口小于 520px 时，聊天使用可用宽度，输入框随之适配，不向外溢出。

自动收起不会写入用户偏好。导航、会话列表、主聊天可见性和右侧面板可见性具有独立状态。停靠空间不足时，导航和会话列表可作为抽屉打开，按 Escape 或点击遮罩关闭。隐藏时预览标签和草稿保持挂载。扩大视口时按用户偏好恢复面板，并留出 24px 恢复余量，避免临界宽度反复切换。预览分隔比例保存在现有会话布局存储中，与可见性分开。

拖动聊天与预览的分隔条，可在两侧最小宽度范围内调整。方向键每次调整 20px，Home/End 移至预览宽度边界，Enter 或双击恢复聊天／预览 55:45 默认比例。聊天或面板菜单中的“恢复默认布局”恢复导航、会话列表和聊天，关闭右面板并重置比例，保留草稿与文件标签。输入表单实际宽度低于 600px 时，次要操作移入“更多输入操作”，模型选择和发送保持可见。共用自动增高 hook 在文字或容器宽度变化后重新调整文本域高度。弹出层限制在视口内；设置页在 650px 以下重排。

输入区实时显示当前轮次成功修改的文件数及新增／删除行数；点击汇总可在右面板打开 diff。轮次结束后，权威变更快照替换增量统计。

<a id="conversations"></a>
## 对话

对话列表包含“项目”和“最近”，已移除独立的“远程项目”分区。远程对话仍出现在“最近”，也仍可经输入框的 Cloud 环境选择器开始新的远程工作。

右键对话可重命名、标记、归入项目或从列表删除。标签和分组保存在本机；移动对话不改变执行目录。删除条目可从“显示已删除”恢复，AX 历史仍保留。切换语言只翻译界面控件，不改变用户文本、生成答案或包描述。语音凭据各有独立显示按钮。

设置 → 显示的语言和主题选择器使用应用共用下拉菜单。模型／提供商、备份和能力作用域选择器使用共用圆角 Radix Select 及主题菜单。设置布尔控件和导入选择使用胶囊开关：左侧标题和说明、右侧控件，行间有分隔线。开启开关使用主题强调色及白色滑块；禁用状态和键盘焦点保持可辨。记忆删除单列操作行，并保留确认对话框。

任务停止后，聊天保留已接收工具调用和输出；刷新历史按调用 ID 合并去重。长时间运行的子会话工具记录来自更新后的 AX 历史回放，Crew 重启后仍可访问。

<a id="imports"></a>
## 导入

设置 → 导入／导出自动扫描用户目录及当前项目中的 Codex、Cursor、Claude Code、Windsurf 和共用 `.agents/skills` 配置，可将技能包或整份 MCP 配置导入当前项目或全局 AX，也可手动选择路径。扫描只读取配置；导入逐项展示，名称冲突交给 AX 拒绝，失败项保留以供重试。插件、导入／导出和本地 AX 在使用所选目录前先验证。已保存目录被删除或不可访问时，显示路径及明确的**选择工作区**操作；取消保留选择，Crew 不静默替换成其他项目。没有有效项目仍可发现用户级来源；选择已有目录后恢复项目扫描和导入／导出。原生扫描器也会跳过无效的可选项目路径，不阻塞用户级发现。每个来源应用默认折叠，显示名称和可用条目数。点击标题或按 Enter/Space 可独立展开／收起 Skill/MCP 列表；折叠后仍保留选中项。重新扫描或切换工作区会重置展开状态；关闭的列表不渲染所有条目，使大型技能集合保持紧凑。

设置成功提示在四秒后或切换设置分区时消失，之前分区的结果不会出现在新分区；AX 操作失败仍以错误保留。移除提供商对 AX 管理及环境变量凭据均使用 `ax auth remove <id>`。AX 记录提供商停用状态，防止环境配置提供商重启后再次出现，同时保留系统环境变量。保存新 API 密钥或重新登录会再次启用它。不支持该命令的旧 AX 会提示更新，不会显示虚假成功。已移除提供商也不出现在 Crew 当前模型选择中。

设置 → 导入／导出通过已安装 AX 的 `skill import` / `mcp import` 命令导入本地 Skill 目录及 MCP TOML 或 JSON，可选项目或全局作用域。使用这些命令需要更新后的 AX 可执行文件。

<a id="subagent-workspace"></a>
## 子代理工作区

会话记录为每次委派的 AX 执行显示紧凑卡片。点击卡片打开右侧**子代理 / Agents**标签并选中对应子代理。标签还提供子代理列表、状态计数、嵌套委派链接、可展开任务指令、流式输出、工具输入／结果，以及最终结果或错误。这里只展示子代理公开消息和工具活动，不包含推理内容。普通委派和队列子任务共用视图，父代理叙述与最终答案保留在主对话记录中。

更新到达时保留所选子代理。滚动到底部时面板跟随新输出，阅读前文时保留位置。复用现有最小 420px 的可调整侧面板、抽屉及键盘行为。文件、预览和聊天保留独立面板状态。侧聊有独立子代理选择和详情视图，并提供“返回侧聊”，避免查看侧聊子代理时选中无关主会话代理。子代理工作视图支持复制和已保存 diff 审查，不将父代理的分支或工作区文件操作应用到隔离的子代理存储。

AX 提供增量式 `sessionUpdate: "subagent"` 信封，Crew 转发为 `subagent.update`，会话历史经已绑定父会话恢复相同信封。旧实时片段与历史合并时，终态不会退回运行中。父任务取消后未完成子代理显示已停止；父任务以其他方式结束且没有子代理回执时显示已中断。详情视图明确指出缺失工作记录。需要更新后的 AX；旧二进制及历史会话可能没有子代理活动。面板不独立控制子代理执行。Android 接受这些增量事件，但不会为每个子代理输出片段刷新任务列表；代理详情工作区仅桌面端提供。

<a id="subagents"></a>
## 子代理

设置 → 插件 → Agents 包含**子代理委派**，可设最大递归深度和并行度。深度 0 禁用委派，1 允许直接子代理，更大的非负整数允许嵌套委派。主模型自行决定何时为研究、写作、分析或编码委派，简单任务可直接完成；修改限制不会启动子代理。并行度接受 1–64，默认 8；深度默认 1。所有层级共享并行上限，等待中的祖先也计入；嵌套准入耗尽时返回失败而非死锁。普通子代理与队列子任务共用限制，继承当前任务权限上限；在统一委派版本 AX 中，深度 0 同时禁用两条本地路径。命名 Agent 开关独立控制预设角色。页面说明模型也可临时分配子任务，不必添加预设角色；无需另设自动委派开关。

现有“全局配置／当前项目”选择器也控制这些设置。Crew 通过已安装 AX 的 `settings --scope` 命令读取／保存，使用 AX_HOME 和选定工作区。两种作用域都显式传入 `--scope`，需要当前 AX 作用域设置／重置接口；不回退到旧全局设置，也不通过帮助输出探测能力。保存在下一轮生效，不干预已运行子代理。打开页面不写设置，保存仅写修改字段，因此修改项目深度不会将继承的全局并行度固定下来。无效值不可保存；保存失败保留草稿并显示 AX 错误。执行 AX 前验证目录，不可用项目显示目录选择指引，而不是进程启动失败或泛化重启建议。读取失败可重试。设置 → AX 不再保留独立 Subagents 开关。

<a id="scoped-ax-plugins"></a>
## 具有作用域的 AX 插件

设置 → 插件打开 `/settings/capabilities`，主侧栏没有独立插件入口。插件页不显示工作区路径或作用域解释文字；作用域选择器仍决定修改位置。设置中的工作区目录、AX 可执行位置、发现的导入来源和插件详情来源均用圆角图标标签显示完整绝对路径，去掉 Windows `\\?\` 前缀，包括 UNC 路径。长路径在可用宽度内换行，不缩写或截断；这只改变显示，原生调用仍传原路径。备份工作区卡片保留目录选择按钮。页面可切换**全局配置**和**当前项目配置**，提供带搜索及计数的 Mod / MCP / Skills / Agents 标签。Skills/Mods/Agents 使用含说明、作用域和开关的图标行，MCP 使用带配置菜单和开关的圆角分组列表。列表适配面板宽度，窄窗口仍保留作用域及启用状态，长名称换行。点击名称查看完整说明和来源。标签支持方向键／Home／End，并关联对应标签面板。搜索可清空；空分类提供对应来源指引。数据到达前计数显示横线；目录读取失败提供重试，不声称未安装插件。

添加对话框有两个可见步骤，并标明目标作用域：（1）从工作区开始选择 Skill/Mod 目录或 MCP/Agent TOML 文件，显示完整路径及更改操作；（2）确认名称。目录来源默认用文件夹名预填，用户已输入时不覆盖；TOML 可能定义多个条目，因此名称由用户填写。两项齐备前禁用添加按钮。原生选择器打开时锁定重复提交和取消按钮；取消选择器保留草稿，失败保留草稿供重试。更换工作区或作用域会清空对话框、搜索及反馈；延迟到达的选择器或变更结果不能更新新视图。写入中禁用作用域切换。变更成功使所有全局／项目目录缓存失效，继承视图也刷新。保存提示四秒后或切换分类时消失。未选工作区时不查询项目目录；选择目录管理插件，或切换全局配置浏览全局目录。

AX 内置工具不是插件，不在此页显示，也不在此展示工具目录读取错误。配置分布式 AX 实例时，Tool 字段提供本机 AX 内置工具名切换按钮，但目标机器 AX 仍是权威来源。可执行能力支持添加、详情、启用、禁用和移除。项目视图包含继承的全局项，在项目中禁用或移除会创建项目屏蔽，不改变全局配置。Crew 经 ACP/CLI 将作用域解析和变更交给 AX 共用注册表，需要支持 `_ax/scopedCapabilities` 的 AX。项目能力文件位于 `<project>/.ax`，命名 Agent 指令仅在委派时加载。

Mod 由 AX 实际会话运行时执行，支持 hook、命令、自定义工具、临时会话状态和持久化的各 Mod 存储。Crew 发送 `_ax/mods` 目录请求，将管理交给 AX。添加的目录须包含 `mod.json` 和 JavaScript 入口。需要更新的 AX 和 Node.js 20.6+；桌面端使用已安装 AX 可执行文件。若该文件对 `_ax/mods` 返回 `-32601`，Crew 提示本地 AX 需要更新，同时继续显示其他目录。只更新 Crew 不会使旧 AX 获得 Mod 支持。启用工作区沙盒，或本地运行时经 SSH 执行时，AX 拒绝 Node Mod。尚未实现 DSH 完整 UI／托管层 API。受支持事件、选项、`/mod:<command>`、生命周期和兼容性限制见 [AX Mod 包与 API 指南](https://github.com/Axium-Labs/AX/blob/main/docs/mods.md)。

侧聊包含主输入框的添加上下文菜单、图片附件／粘贴／拖放预览、原生工作区文件引用、权限菜单、模型／思考强度弹出卡片、Fast 模式、语音输入、停止和发送。本地创建传入所选提供商／模型，远程创建使用所选成员。已创建侧聊保留原模型和工作区；思考强度及权限选择只作用于后续轮次，执行中补充指令保留当前轮次策略。文件引用使用规范化工作区读取器。发送失败保留文本和附件。语音输入由浏览器 Web Speech 提供，不支持的 WebView 禁用麦克风并说明原因，不使用已存 Xfy 凭据。Escape 优先关闭打开的输入菜单，保留侧面板。

<a id="distributed-management"></a>
## 分布式管理

侧栏**分布式协作 / Distributed**打开 `/distributed`。工作区、节点和活动视图整理现有 Goal/Task 协作、Host → AX Instance 管理以及 Execution/Session 历史，支持参与者职责、作用域策略、实时 ACP 指导／审批、共享容量、整个 Workflow 的暂停／恢复／取消／重试、重新分配、需确认的批量操作，以及主动选择的目标原生设置／插件。Long Project 保持可选，内联于 Goal 中。此可选界面基于现有持久化集群和 AX 管理的会话／设置；旧设备控件仍可使用。策略与工作节点配置见[分布式协作](../distributed-collaboration.zh-CN.md)。

创建及添加工作对话框采用三步向导，步骤导航与操作底栏固定，内容区域滚动。创建首先显示等大的 Task/Goal 选项。成员分别展示 AX/Host 标识和在线状态，选中后在标识下方显示职责与模型设置，不挤压名称。可用成员超过四个时提供 AX/Host 搜索。编号工作任务卡片包含分配、模型覆盖和依赖。确认步骤汇总工作、职责、模型、资源最低要求及当前节点匹配原因。返回上一步保留草稿；深浅主题、窄或低矮窗口中控件仍可访问。


<a id="connections-and-named-projects"></a>
## 连接和命名项目

在**添加项目**中，选定来源文件夹后名称可选。名称为空或仅空白时使用路径最后一段，支持 Windows、UNC、POSIX 及尾部分隔符；文件系统根目录使用盘符或根标签。名称框以占位文字预览该默认值。更换文件夹更新默认名称，不覆盖用户明确输入的名称；清空自定义名称后恢复文件夹默认值。本地、SSH 和配对设备目录选择均遵循此规则。创建仍需来源目录，请求失败保留名称草稿和路径供重试。桌面端通过现有项目 API 发送解析后的名称。

<a id="project-terminals"></a>
### 项目终端

打开桌面终端或按 Ctrl+Backquote，会跟随当前显示对话绑定的主机和项目目录；新对话使用其所选环境。本地项目启动已配置的 PowerShell/CMD/Git Bash/WSL Shell。SSH 项目在原生 PTY 内直接启动 OpenSSH，使用 `-tt`、已保存的主机/端口/身份文件，以及安全引用的远程 `cd`，再进入远程用户的交互式 POSIX Shell。该终端不要求远程安装 AX，SSH 目录也绝不在本地磁盘校验。OpenSSH 读取桌面用户的 SSH 配置与 agent、检查 known hosts，并可显示常规交互认证/主机密钥提示；这与 Agent SSH 工具的非交互认证相互独立。

终端面板可见时，切换主机或目录会选择已有匹配终端，或打开新终端。隐藏面板保留进程，重新打开时选择当前项目。页签保留原主机/目录，并始终可手动选择。标签只显示目录名，悬停显示完整初始路径；不显示 local/SSH 前缀或重复位置行。本地与 SSH 终端均由 Shell 提示符正常显示当前目录。远程目录匹配区分大小写。终端总数最多八个；达到上限时，新项目没有活跃终端，需关闭一个页签再点 +。SSH 启动或远程 `cd` 失败时绝不回退打开本地 Shell。关闭页签会结束本地 SSH 传输；启动中关闭也会关闭迟到进程。创建期间到达的 ConPTY 光标报告会缓冲，供 OpenSSH 使用。

项目元数据未解析或远程环境未选择时，不打开本地终端。配对 AX 设备目前没有交互式终端网关协议，面板会说明需要 SSH 连接。此变更不新增远程文件浏览，也不改变 Agent 任务放置。SSH 主机仍需 POSIX Shell，桌面机器必须安装真实 SSH 客户端。

旧手机连接路由现在打开 Connections。Control this computer 显示待批准/已授权设备，并提供允许、拒绝与撤销；Add device 打开 Android 连接说明。Control other devices 列出配对 AX 并链接配对管理。SSH 提供网关用户主 ~/.ssh/config 中的明确别名、多选，以及手动填写 host/user、可选端口和身份文件路径的表单。

保存 SSH 主机会持久化设置；Connect 通过 OpenSSH 探测远程目录。SSH 使用本地 AX 与本地模型凭证，经 ssh 工具发送远程 Shell 命令；远程无需 AX 或模型凭证。OpenSSH 使用非交互默认/agent 认证或密钥路径，校验已知主机密钥并接受首次遇到的主机。不支持密码和密钥口令提示。远程目前需要 POSIX Shell 和支持深度/NUL 输出的 find（Linux/macOS）。

所选项目提供默认 SSH 主机与远程 cwd。同一 AX 对话内，ssh list 显示全部已保存活跃主机；ssh exec 可指定其他 host_id，因此一个本地 AX 可操作多台主机。注册表、任务调度器与独立主机工具调用不设置固定 SSH 主机/任务数量上限。同轮内影响同一主机的调用仍遵循资源顺序，并继续执行审批。普通本地/配对 AX 的任务上限沿用原配置。

SSH 会话记录工作区保存在本地 AX_HOME/ssh-workspaces/{host-id}，远程源码 cwd 与此路径分离。后续对话/历史重放与删除使用本地 AX；SSH 离线或被撤销后历史仍可读。重启后 SSH 初始离线，新工作需先 Connect。隔离进程回归使用真实本地 AX 和测试 OpenSSH 替身后的 POSIX Shell：264 个保存主机（清单超过 Windows 环境大小限制）、单轮六主机，以及八个同成员并发任务。未实测外部 SSH/网络认证。

AX 的 WSL 执行设置也转发 SSH 上下文，并将密钥路径转换为 Linux 路径。WSL AX 必须包含新的 SSH 工具，其 OpenSSH 配置必须能解析所选别名。

Add project 询问名称、来源主机和一个目录。本地 Tauri 使用原生目录选择器，浏览器预览使用工作区 API；SSH 以登录账号浏览目录。配对 AX 仅列出已注册工作区根目录，保留桥接白名单；应先在该主机通过 AX 注册目录。移除项目会保留成员和已有对话历史。


Goal 标签通过共享 `settings.goal` 键跟随界面语言（目标 / Goal）；API 字段、原生命令和用户内容保留原值。


<a id="collaboration-editing"></a>
### 协作编辑

分布式工作区填满可用宽度，各视图拥有各自操作：Nodes 中单一 Connect AX 入口、Workspace 中创建入口，刷新位于页签旁。Edit collaboration 使用响应式卡片保存名称、描述性目标和成员，新增成员时可选同时添加新工作。任务详情支持重命名、首次执行前编辑输入，以及确认后移除。已开始的输入作为历史保留；需求变化应发送 Session 指导或添加替代工作。依赖检查保护移除，Activity 保留执行历史，保存失败/过期时保留草稿。持久化、围栏隔离与编辑限制见[分布式协作](../distributed-collaboration.zh-CN.md)。


生命周期操作显示依赖阻塞项并要求确认。轮询保留当前协作与元数据草稿。成员选择器排除已删除实例，保存时清除失效选择；历史视图保留归档参与者名称，并标记已移除 Host 的固定分配。事务、围栏隔离和历史保留规则见[分布式生命周期约定](../distributed-collaboration.zh-CN.md#removing-and-cancelling-collaborations)。

## 显示配色主题

“设置 → 显示”将深色、浅色和跟随系统保留为独立外观模式。配色选择器包含原 AXCrew 配色与 28 套适配应用的风格：ChatGPT、Absolutely、Ayu、Catppuccin、Dracula、Everforest、GitHub、Gruvbox、Linear、Lobster、Material、Matrix、Monokai、Night Owl、Nord、Notion、OG、One、Oscurange、Raycast、Rose Pine、Sentry、Solarized、Temple、Tokyo Night、Vercel、VS Code Plus 和 Xcode。每项显示色样并支持键盘选择，深浅变体均更新 Shell、对话界面、设置弹层和终端。模式与配色在本桌面独立保存；已有偏好保留 AXCrew 配色，选择 AXCrew 即恢复原颜色。这些是 AXCrew 自行适配的配色，不是导入参考应用的主题定义。

会话列表和侧面板展开/收起时使用滑动、淡入淡出，并遵循系统减少动画偏好。展开面板提供内部收起操作；关闭后使用聊天栏入口，且面板退出键盘焦点顺序。

Android 截图与局域网授权限制见 [Android 能力](../architecture/android-migration.zh-CN.md)。

“设置 → 聊天平台”配置账号文本对话。切换平台保留其他平台未保存字段与扫码进度。支持平台、配套依赖、回调要求和授权统一记录在[聊天渠道](../chat-channels.zh-CN.md)。

### 网页预览与精简变更审查

桌面对话侧栏提供可调整大小的 Preview 页签，含 HTTP(S) 搜索/地址栏、重新加载和起始页按钮。裸域名使用 HTTPS，localhost 和回环地址使用 HTTP，关键词提交后打开 Bing。桌面使用原生子 WebView，网站与搜索结果作为顶层页面加载，而非 iframe。圆角导航控件提供后退、前进与重新加载，胶囊地址栏使用轻微焦点边框。地址占位文字左对齐，聚焦后消失。浏览器标签栏可独立添加、切换和关闭页面；非活跃原生页隐藏，但保留状态与历史，标签显示页面标题。主题化起始页提供本地服务器快捷入口。浏览器开发模式仍使用 iframe，对禁止嵌入的网站提供新标签链接。
当前对话中发现的本地开发服务器 URL 以按钮呈现，仅点击后加载；内嵌交互页可接收开发服务器实时更新。拒绝含凭证 URL、特权 scheme 与应用自身 origin，包括原生导航。远程项目需要可访问 URL 或已转发端口。切换对话会清空普通预览 UI 页签；AX 控制视图则为其运行 Session 隐藏并保留，不关闭。每个子视图跟随面板裁剪后的物理像素边界，计入 UI 与显示缩放，并在应用对话框/菜单下隐藏。普通用户预览的新窗口链接创建新标签；受控页拒绝全部弹窗，需明确 goto 授权。下载禁用，远程页不获得应用能力。面板不会自动启动服务器或转发端口。

Ask AX to inspect 将预览 URL 放入输入框。本地桌面 AX 通过经认证的回环桥，使用已有 `browser` 工具操作这些子 WebView，不另开 Playwright 窗口。`list_sessions` 发现该 AX Session 的标签页，默认操作活跃绑定页；`open`/`goto`、文本/CSS 目标快照、点击、填入、输入和 Enter/Tab 均作用于此页。Agent 创建的页自动出现在 Preview。切换对话仅隐藏受控标签，不销毁正在进行的浏览器工作；关闭标签或返回 Start 会关闭原生视图。
受控标签标为 AX controlled。Browse in a new tab、地址导航和 Reload 打开独立普通预览，不放宽受控页网络边界；受控副本的 Back/Forward 仍禁用。标签按真实 AX Session ID 路由，不按会话标题。每 Session 最多 16 页，每桌面进程最多 64 页，可明确关闭不用的标签。

Agent 首次接管已有用户页面时，先安装网络保护再重新加载，因此 DOM/表单状态刷新，但内嵌浏览器原有 Cookie/登录配置继续使用。Session 路由只隔离标签访问，不隔离浏览器配置文件。既有 Cookie 与预先存在的独立用户配置 worker 不隔离；受控文档绕过缓存/Service Worker 响应，禁止创建新 worker。Windows 要求 WebView2 支持全请求来源过滤与 DevTools 拦截。保护层阻止跨源 HTTP 资源/重定向、WebSocket、全部受控页弹窗与下载；空闲 Agent 受控标签不能继续后台请求。保护层安装失败则操作失败。其他桌面平台当前报告内嵌 Agent 控制不可用，但普通用户预览仍可用。截图和 Enter/Tab 之外的按键明确不支持。不接受模型提供的任意 JavaScript，远程页没有 Tauri IPC 能力。

Browser Use 启用状态、网站 Ask/Allow/Deny 和任务限制仍以 AX 为权威。桌面桥凭证逐次启动生成，不进入工具/MCP/Mod 子进程环境，也不持久保存。远程配对/SSH AX 不继承本地浏览器连接，而使用自己的运行时。本地内嵌桥不可用时，不会静默回退到外部浏览器。

文件变更摘要使用紧凑行、对齐计数、截断路径和完整路径提示，并复用侧栏 diff 查看器；不可用的撤销操作不显示。已允许的 Computer Use 应用不再触发普通逐动作确认；显式任务 Ask/Deny 与能力 Deny 仍然生效。网站规则不变。

聊天平台设置的默认项目目录可选。在已授权私聊中，可直接使用 `/projects`、`/project`、`/new`、`/sessions`、`/session` 选择项目/会话；默认目录不移动既有对话。详见[聊天渠道](../chat-channels.zh-CN.md)。

聊天平台配置说明自然语言菜单入口（`菜单`、`切换项目`、`查看历史会话`）和编号选择，也支持直接新建会话、项目名及状态/取消短语。斜杠命令仍可使用。

账号配对引导说明首次批准后的自动欢迎菜单，以及 `菜单`/`怎么用`/`你能做什么` 帮助短语。没有项目的普通消息打开选择器；新建/切换确认附带简短菜单提示。

本地项目菜单始终提供 **Remove from project list**，包括从 AX 历史自动发现的项目。移除在本桌面持久保存，不删除项目文件或对话，再次添加目录即可恢复。永久删除本地对话时，以该 Session 发现的 AX 数据目录为目标，包含旧版与自定义存储；AX 确认删除后，Crew 才移除相关任务记录。

会话导航圆点表示尚未阅读的完成/失败结果。任务和 Session 列表均成功加载后，清除那些已无任务/会话绑定的恢复通知。较晚到达的 Session 绑定会被协调，使打开对话能清除对应结果圆点。任务列表刷新期间到达的新完成事件仍保留。
